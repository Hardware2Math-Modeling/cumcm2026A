## 2. 各角色的产出契约

一方的东西必须**结构化到另一方能直接消费**，否则交接就变成口头沟通。

### `@model` 必须产出

| 文件 | 内容 | 谁消费 |
|---|---|---|
| `docs/model/qN.md` | 控制方程、无量纲化（如有）、边界/初始条件、离散格式、稳定性条件、求解步骤 | `@impl` 照着写代码；`@paper` 照抄公式 |
| `docs/model/correlations.md` | 附录 2/3/4 三套经验公式的整理、量纲校验、适用范围 | `@impl` 照着实现 |
| `docs/NOTATION.md` | 符号表（符号 / 含义 / 单位 / 首次出现处） | 三方 |
| `docs/DECISIONS.md` | 每个建模选择 + 理由 + 被否决的方案 | 三方 |

**硬要求：`docs/model/qN.md` 里的公式必须能逐行翻译成代码。** 「大致用有限差分」「考虑用隐式」这种话不算交付。要具体到：
- 用哪个差分格式（前向/后向/中心/Crank–Nicolson）
- 边界条件的离散形式（虚拟节点法还是单侧差分）
- 非线性项怎么处理（显式滞后 / Newton 迭代 / 固定点迭代）
- 时间步进用哪个积分器

### `@impl` 必须产出

| 文件 | 内容 | 谁消费 |
|---|---|---|
| `src/common/` | 物性公式、单位转换、xlsx 读写、绘图样式 —— **接口按 `docs/INTERFACES.md`，不许自行改签名** | `@model` 核对、`@paper` 引用 |
| `src/qN/` | 第 N 问的求解器 | — |
| `scripts/` | `parse_attachments.py`、`run_qN.py`、`make_tables.py`、`make_figs.py` | 所有人 `make` 调 |
| `tests/` | 见下 | — |
| `results/resultN.xlsx` | **交付物** | `@paper` 的表格由它自动生成 |

**测试的最低要求**（数模竞赛也要有，否则数值结果不可信）：
- **守恒性**：无源无汇时总质量/总能量随时间的变化应趋于 0（或只经由边界流失，且流失量等于边界通量积分）
- **收敛性**：网格减半时误差按预期阶数下降（至少验证一阶/二阶）
- **边界条件**：`r=0` 的对称条件、`r=R` 的对流条件在数值解上确实成立
- **极限情形**：把参数取极限（如 D→0、h→∞）时解退化到解析可预期的行为
- **格式**：`result*.xlsx` 的工作表名、行列数、小数位数与模板一致

### `@paper` 必须产出

| 文件 | 内容 |
|---|---|
| `paper/main.tex` 及 `preamble.tex` | 论文骨架、宏包、格式 |
| `paper/sections/00_abstract.tex` | 摘要（最后写，最先改） |
| `paper/sections/01_restate.tex` | 问题重述 |
| `paper/sections/02_assumptions.tex` | 模型假设（**每条假设要写清代价**） |
| `paper/sections/03_notation.tex` | 符号说明（**从 `docs/NOTATION.md` 生成，不要手抄**） |
| `paper/sections/04_q1.tex` … `07_q4.tex` | 四问的模型、求解、结果、分析 |
| `paper/sections/08_evaluation.tex` | 模型评价、优缺点、改进方向 |
| `paper/sections/09_conclusion.tex` | 结论 |

**引用规则**：表用 `\input{tab/tabN}`，图用 `\includegraphics{figs/xxx.pdf}`。**论文里不许出现手打的数字表格。** 审稿时如果发现 `paper/sections/` 里有 `\begin{tabular}` 包着一堆手抄数字，直接打回。

## 3. 谁审谁的 PR

三条线文件集互不相交，所以**自己审自己的集成分支**，只有两种 PR 需要他人：

| PR 方向 | 必须 reviewer | 原因 |
|---|---|---|
| `impl` → `main` | `@model` | 校验代码是否忠实实现了模型 |
| `model` → `main` | `@impl` | 校验公式是否可实现、量纲是否自洽 |
| `paper` → `main` | `@model` | 校验论文里的公式与符号没走样 |
| 任意 → `main`（改了共享基础设施） | 全部三人 | 见 `docs/BRANCHING.md` §5 |
| 任意 → 任意集成分支 | 无需 | 同一角色内部事务 |

**reviewer 的唯一职责是回答一个问题：「这份产出能不能被我用？」** 不评价风格，不要求重写。有异议 → 写进 `docs/DECISIONS.md`，别在 PR 里吵。

## 4. 每日同步（15 分钟，不可省）

每天固定时间（建议午饭前）三人各答三个问题，答案直接写进 `docs/TASKS.md` 的当日区：

1. **昨天产出了什么**（给出文件路径，不给形容词）
2. **今天要产出什么**（给出可验收的定义）
3. **被什么卡住了**（要具体到「等 `@model` 给边界条件的离散形式」这种粒度）

**卡住超过 30 分钟必须喊人。** 竞赛里最贵的是三个人各自沉默地卡住。
