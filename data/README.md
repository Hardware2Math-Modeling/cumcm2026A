## 1. 目录约定

| 目录 | 内容 | 是否入库 |
|---|---|---|
| `data/raw/` | 从 `problem/附件/` 解析出的**只读副本**（csv），不改内容 | ✅ 入库 |
| `data/interim/` | 中间清洗结果，**随时可由 `data/raw/` 重建** | ❌ 忽略 |
| `data/processed/` | 建模直接使用的规整输入（插值后的时间序列等） | ✅ 入库 |

**规则**：任何代码都**不许直接读 `problem/` 下的 xlsx**（除了 `io_excel.read_template` / `read_attachment` 这两个入口）。
一律先 `make data` 解析到 `data/processed/`，再从那里读。这样原件冻结，且数据管道可追溯。

## 4. `problem/附件/附件3/result1~4.xlsx` —— 交付模板

**唯一真源。** 写 `results/result*.xlsx` 前必须先读模板（`AGENTS.md` 铁律 3）。
下面的内容是 `make probe` **实测**得到的，不是从题目文字猜的：

| 文件 | 工作表名 | 时间步长 | 最后一列表头 |
|---|---|---|---|
| `result1.xlsx` | `温度`、`水分浓度` | **1 s** | `2` |
| `result2.xlsx` | `温度`、`水分浓度` | **1 s** | `2` |
| `result3.xlsx` | **`Sheet1`** | **60 s** | `2` |
| `result4.xlsx` | **`Sheet1`** | **60 s** | **`药材表面`**（文字） |

### ⚠️ 实测推翻的四个直觉

1. **时间单位是秒，不是小时。**
   题目表 3~表 6 的表头写的是 `h`，但模板 A 列的示意数据是 `1`（result1/2）和 `60`（result3/4）——**秒**。
   → 交付文件用秒；**论文表格才用小时**。这个区分见 `docs/NOTATION.md`。

2. **距离列是完整的 21 列，模板里的 `…` 是省略号。**
   模板列头是 `0, 0.1, 0.2, …, 2`，其中 `…` 是一个**文字单元格**。
   实际输出应为 `0, 0.1, 0.2, …, 2.0` 共 **21 列**（对应题目"距离每隔 0.1 cm"）。
   → 少写列会在 `io_excel.write_result` 的校验里被拦下。

3. **result3 / result4 的工作表名是 `Sheet1`，不是 `水分浓度`。**
   而 result1 / result2 是 `温度` + `水分浓度`。

4. **result4 的最后一列是文字 `药材表面`**，不是数值 `2`。
   前 20 列是固定物理位置 `0 ~ 1.9`，末列是**当时**的表面值（表面会从 2.0 收缩到 1.198 cm）。

5. **A1 是斜线表头** `时间\到药材中心的距离`（既表时间也表距离）。

这些结论固化在 `src/common/io_excel.py` 的 `LAYOUTS` 里，
并由 `tests/test_framework.py::test_layout_matches_real_template` **守门** ——
赛方若更新了模板，这个测试会立刻失败。

**待办**：`@impl` 复核上表；`tests` 里的守门测试就是复核工具。
